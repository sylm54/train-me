# Scripted routines overhaul (format v3)

Replace the markdown/page routine system with **front-matter JS scripts** and reduce TTS to a pure, prerendered audio layer. Interaction, visuals, voice capture, and data collection move into an orchestration JS API that plays audio, awaits zones/marks, and shows stateful widgets on a z-layered grid.

Clean break per your answers: no v2 compatibility, interactive/visual TTS tags removed now, `.js` files with comment front matter, runtime sandboxed.

## Target architecture

### 1. Routine/task files (`routines/*.js`, `tasks/*.js`)

```js
/*---
title: Evening Voice Drill
schedule: 0 20 * * *
timeframe: 45m
success: { "type": "points", "delta": 15 }
---*/
const gif = await show('media', { source: 'redgifs', niche: 'tik-tok', every: '4..8', z: -1, area: 'full' })
const s = await audio.play('hypnos/warmup.xml')
await s.mark('deep')
const drill = await show('voice', { analyzers: ['pitch','resonance'], duration: 30, requiredScore: 0.75 })
if (!drill.passed) await show('text', { text: 'Again. Slower this time.' })
await drill.save('drill-' + vars.date)           // recording → agent_data/recordings/
await s.resume()
await s.end
log('voice', 'drill', { score: drill.score, metrics: drill.metrics })
hide(gif)
```

- Front matter: same `parse_kv_block` grammar, same keys as today (`title`, `schedule`, `timeframe`, `success`/`failure`, `cooldown`, `limit`, task `timeoffs`). Everything engine-owned stays declarative: occurrences, reconcile, idempotent actions, exemptions are untouched.
- The `/*--- ... ---*/` wrapper is parsed by Rust; the rest of the file is the raw JS body.
- Habits (`habits/*.md`) and store (`store/*.json`) are unchanged.

### 2. JS runtime — sandboxed iframe, boa for validation

The script runs in a hidden `<iframe sandbox="allow-scripts" srcdoc=...>` (opaque origin: no DOM, no Tauri invoke, no fetch, no localStorage), wrapped as:

```js
(async ({ wait, show, hide, audio, media, log, vars, notify, fail }) => { /* body */ })()
```

so your `await wait(1)` syntax works verbatim. All timing is **parent-driven** (`wait` executes `setTimeout` in the parent and posts back), dodging hidden-iframe timer throttling. The bridge is a postMessage RPC layer (~200 lines) plus event push (widget state changes, marks reached, playback end).

Why not boa as the runtime: every controlled resource (ManifestPlayer, widgets, mic engine, activity logging) lives in the webview; a Rust-side engine would add a second IPC hop to every call and a Rust↔TS mirror of the whole API. The iframe runs the same V8 as the app with one hop. **boa is still added — as `boa_parser` (parse-only, light) — so `validate_files` reports real JS syntax errors** at authoring time; framework-cli validates via the `AsyncFunction` constructor in Bun.

Lifecycle: script resolves → success (`v2_finish_run`); throws / `fail(reason)` / give-up → `v2_fail_run`; errors shown in the UI and logged. Resuming an in-progress run restarts the script from the top (documented).

### 3. TTS: audio-only, one file-audio surface, zones/marks (manifest v5)

**Removed tags:** `<until>`, `<choice>`, `<rating>`, `<react>`, `<beatmeter>`, `<visual>` (+`<caption>`), `<if>`/`<else>`, `<intro>`/`<main>`/`<outro>`, **and `<sound>`**. The embedded sound-effect system dies with them: `sounds.rs`'s `SoundType` table, the 15 WAVs in the app binary, and the `get_sound_names` command are deleted. Player prompt/choose machinery, cond evaluation in the player, the repeat slider, baked visuals, and beat baking all go.

**Kept:** `voice/speed/volume/pause/tone/effect/overlay/part/loop/background/random/scramble/include` (incl. glob) — `<tone>` stays as the procedural waveform layer; prerender pipeline, include dedup, ONNX synthesis, render-progress UX unchanged (hard constraint: scripts stay prerendered).

**Added — `<clip>` as the single pre-rendered audio surface:**
- `<clip src="sounds/beep.wav" volume speed>` — plays any media file from the sandbox: framework-shipped sound effects, saved voice recordings, anything the framework drops in. Works everywhere `<sound>` worked (foreground one-shots, `<background>`, `<overlay>` parts, `<loop>`).
- Decode via `hound`, linear-resample to the TTS rate; the file's content hash joins the manifest freshness hash (the `glob_digest` pattern). WAV-only in v1 (mp3/other decoders = follow-up); validation checks src exists.
- The sound library becomes framework content: the 15 WAVs move from the app's `src/sounds/` into the framework's `agent_files/sounds/` (coordinated change in the framework repo; the app ships no sound content).
- Sandbox files get served to the webview through a new token-authed route on the existing loopback audio server (`/files/<sandbox-relative-path>`, same auth as `/tracks`) — used by the beatmeter widget's click sample and the media widget's local-file mode.

**Added — structural markers:**
- `<zone name="...">...</zone>` — container, transparent to audio, a manifest node and a segment split point.
- `<mark name="..."/>` — self-closing zero-length marker, also a split point.

Prerender priority heuristic: regex-scan JS bodies for quoted `*.xml` paths (honest heuristic, full sweep still backs it).

### 4. Audio API — `ScriptHandle` (wraps ManifestPlayer)

```js
await audio.prepare('hypnos/x.xml')      // trigger render + prefetch, resolves when ready
const s = await audio.play('hypnos/x.xml') // renders on demand (progress UI), then plays
s.pause(); await s.resume(); s.stop(); s.setVolume(0.5)
s.position; s.duration                     // live, from always-on per-segment ticks
await s.end                                // resolves when playback finishes
await s.mark('deep')                       // resolves on entering mark/zone
s.timeUntil('deep')                        // nominal seconds (random counts first option)
s.seek('zone:main')                        // restart the walk at that node (v1: enclosing backgrounds are lost)
s.loopZone('main', 3)                      // programmatic main-looping replaces the old repeat slider
```

ManifestPlayer changes: emit node-entry events for zone/mark, always-on progress ticks (not just beatmeter segments), seek-to-node, volume/speed, remove prompt/cond/beat/visual paths. Multiple handles may play concurrently; the exclusive audioBus claim is reworked (stage owns audio; mic + playback coexist).

### 5. Widgets — stage grid

`ScriptSessionView` renders a Stage (CSS grid, 6 cols) + status chrome (title, give-up, render pill, mini-player strip, **forced red dot whenever the mic is live** — app chrome, not widget-controlled). Widgets overlap freely; `z` sets stacking; `area` = `full` | `{col,row,cols,rows}` | named presets. Handles: `await w.done`, `w.state` (synced snapshot), `w.set(patch)`, `w.on/once(event)`, `w.remove()`/`hide(w)`.

v1 catalog (each reusing existing internals):
- `text` (markdown), `checklist`, `buttons` (await pick → label), `slider`, `input`
- `timer` (countdown, `await done`; count-up clock mode)
- `media` — today's VisualStage + visual.rs/RedGIFs cache as a widget (`source/niche/tags/query/order/every/bpm/count/captions/effect` props, local sandbox files or URLs via the `/files` route); `media.prefetch(cfg)` for warm-up; default `z:-1, area:'full'`
- `beatmeter` — free-running, or `{sync: scriptHandle}` binding the existing BeatScheduler to the handle's active element; click sample is a sandbox clip path (`sound: 'sounds/click.wav'`) fetched via `/files`
- `voice` — the existing tracker stack (pitch/resonance/intonation/weight/loudness/genderspace) as a widget; `.done` → `{score, passed, metrics, lines}`; `.save(name)` records raw PCM from the frame loop, encodes WAV in TS, writes `agent_data/recordings/<name>.wav` via `write_data_file` — playable in TTS via `<clip>`
- `lock` — chastity gate UI wrapping existing commands

Data: `log(feature, action, details)` → activity.db (structured details; the agent aggregates/pre-analyzes in JS before logging). `vars` = read-only run-context snapshot (points, streak, locked, weekday, …). `notify(text)` toast. No points/actions API from JS in v1 (front-matter actions only) — flagged as follow-up with seq-keyed idempotency if wanted.

## Implementation phases (each compiles, gets committed)

1. **TTS audio-only + `<clip>` + zones/marks**: tag_parser/audio_renderer/manifest v5 (remove interactive/visual/beat/if/sections/sound, add clip/zone/mark), delete the embedded sound system, `/files` audio-server route, manifestPlayer cleanup + node events + seek, simplified overlay (non-interactive preview remains for standalone playback), jinglePlayer simplification, tts-tags docs rewrite.
2. **format v3 + engine + minimal runner**: `.js` routine/task parsing (comment front matter + raw body), `boa_parser` syntax validation in `validate_files`, `v2_start_run` returns `{body, vars}`, ScriptSessionView with iframe runtime + `wait/log/vars/notify/fail` + give-up/error UI; delete the page runner, feature blocks, SessionView page model, and the now-dead condition DSL (cond.rs/cond.ts); FORMAT.md rewrite.
3. **Widget framework + core widgets**: stage grid, registry, state/event sync, `text/checklist/buttons/slider/input/timer`.
4. **Audio API**: ScriptHandle full surface, on-demand render integration, mini-player chrome, audioBus rework.
5. **Media + beatmeter widgets** (visual.rs backend, prefetch, BeatScheduler sync via `/files`).
6. **Voice widget + recordings; lock widget; red-dot chrome.**
7. **Agent surface**: docs/internal seed (JS authoring reference + worked examples), `examples/` update, framework-cli validate.ts (front matter + syntax + API lint), skills (framework-dev, tts-tags) update, dead-code sweep. Coordinate moving the 15 sound WAVs into the framework repo's `agent_files/sounds/`.

Verification: `cargo test` for parser/manifest changes (new tests for front matter, clip/zone/mark, v5 manifest), frontend typecheck/build, and manual run of a seeded example routine exercising wait → audio.play → mark await → widgets → voice → log. Version bump via the bump-version skill after phase 7.

Risks accepted: seek drops enclosing backgrounds (v1), `timeUntil` is nominal through random/choice nodes, resume restarts scripts, WAV-only clips in v1, iframe bridge adds one indirection to debugging (mitigated by piping errors/console to the parent log).

Follow-ups (explicitly out of scope): `tm.actions` mid-run points/tasks, general sandbox file API for JS, compressed clip formats (symphonia), extra widget types (spiral/strobe), boa-as-runtime if routines ever need to run without a webview.
